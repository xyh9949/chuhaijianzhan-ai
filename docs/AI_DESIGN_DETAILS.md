# 挑选区块内部的AI调整

适用0.31.1（内部挑选自0.31.0提供）。入口：**全站设计 → AI设计整个网站 → 逐页看效果与继续调整 → 只采用部分修改 → 挑选页面内区块 → 挑选区块内部**。用户自行配置AI；挑选已有候选不会重新调用模型。

## 怎样操作

先生成或打开方案，再展开想检查的区块。可独立调整的区块会显示内部选项，例如主标题、产品说明、图片或内部产品列表。只勾选满意项目，然后“预览选中修改”，核对新的修改前后真实页面，再确认应用到网站草稿。

原整页和整块选择保持。只选内部项目时，页与区块显示半选；即使内部项目全部勾上，也继续使用精细范围。0.31.1完整区块选满也不自动升成整页。内部清单只列AI实际修改的完整子树，不代表该区块的全部内容。自动改成整块可能扩大到后来手工编辑的兄弟，因此只有明确点“整块采用”才扩大范围。

例如方案调整了首屏标题和说明。生成后，你又手动更新了首屏产品列表。选择两个内部项目会采用新标题和说明，保留手改产品列表；明确选择整个首屏时，系统仍按整块检查冲突，不会直接覆盖。只有一个内部项目也能精细采用，不会因全部选中而失去精度。

可以关闭并保留未提交选择，刷新恢复后继续。每次改变选择都必须重新生成组合预览，不能从旧效果直接保存。采用后仍在原生拖拽编辑器中，公开网站仍需原发布流程。

## 哪些内容会一起处理

系统从冻结的原生树计算一组互不重叠的完整子树。只有父级类型、样式和其它配置、插槽及直接子节点身份顺序保持时才继续下钻。出现内部增删重排、父属性改变或内容跨分支迁移时，停在最近需要整体处理的父树，避免重复、遗漏或继承样式失效。

例如一个容器内的两栏互相搬移内容，两栏需要一起采用；容器外另一个独立标题仍可单选。页级g1结构依赖组继续整组处理，不再拆出其内部选项。页面共同设置、旧zones和过大布局等仍按原规则退回整页。

它不是所有节点和任意属性的选择树，界面只列服务器确认可独立采用的项目。绑定的动态产品卡片、同步区块等不会展开为第二套编辑格式；选择对应列表或引用子树时，实际需要的独立资源一起核对和带入。页眉页脚、全站风格及独立详情模板候选继续各自原有的整体审核，不提供内部细项。

## 冲突、权限和撤销

选择使用当前工作区作为新基线。未选兄弟内部的文字、样式及后代编辑可保留；选中子树或共同祖先配置、插槽、直接子节点结构后来变化时拒绝覆盖。生成后新增的锁同样生效，最终组合仍检查锁定内容、完整位置路径和祖先样式。需要的卡片、菜单和图片失效时拒绝不完整组合，未选资源不扩大依赖冲突。

候选分别最多200个区块单位和200个内部单位，每次总计最多103个单位。一个父区块的内部前沿超过预算时，整份内部清单不展示并保留整块，不能截掉半份。源树及混合预算仍为每侧100根、300节点、16层，混合超预算拒绝。

采用与撤销继续保护整个受影响页面。组合预览后新增同页编辑需要重新预览，采用后的同页手改会阻止危险撤销。七天撤销窗口、40分钟候选、原配额与连续挑选深度不变。继续AI调整仍按页面范围；未选状态不是永久锁。

MCP沿用原`site_design_select`与权限，新增只读`detailUnits`元数据。外部客户端只能提交服务器的单位ID，不能拆子树或把内部全选替换成整块；父子重选拒绝。`detail:d1:<hash>`是独立身份，旧section/g1 ID及历史回执不改。详情权限按页面→实际可见父区块→单根归属检查，私有设计约定仍需单独权限。没有新增直接保存、发布或长期偏好写入权限。

## 升级与维护

派生的细项方案继续保存为原生整页 Changes。切回旧版本前，先在隔离副本验证旧程序能读取、预览和处理已有候选。[升级和回退](../DEPLOYMENT.md#升级和回退)

升级细分前沿、祖先比较、锁、执行差异或依赖闭包时，应重新验证选中范围、采用和撤销。
