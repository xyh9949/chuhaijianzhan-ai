# 询盘来源与销售跟进

询盘列表提供有限的来源线索和内部跟进功能。公开表单的接收、通知与保留策略见[网站表单说明](WEBSITE_FORMS.md)。

## 从列表处理询盘

进入“客户询盘”后，可按状态、联系人/邮箱/公司/产品搜索、国家地区及跟进范围筛选。跟进范围包括全部、我负责的、待分配、已到期和高优先级；待分配也包含原负责人已不可用的记录。打开详情可同时查看来源、提交当时的完整答案、跟进信息和内部历史。

| 字段 | 含义与规则 |
| --- | --- |
| 负责人 | 选择当前可用的管理员或编辑成员；可清空为未分配，不向负责人发送消息 |
| 优先级 | 普通、较高、紧急；旧记录界面默认普通，不自动改写数据库 |
| 下次跟进 | 按输入设备当前时区选择，转UTC保存；摘要按站点时区显示，留空表示未安排 |
| 有效性 | 待判断、有效、无效，由成员根据真实需求与沟通人工判断；不是平台认证或自动评分 |
| 处理备注 | 可修改的单份内部说明，最多10000字符；沿用原备注数据和恢复入口 |
| 新增内部跟进记录 | 保存后追加到历史，服务器记录作者和时间；每条最多2000字符，每个询盘最多200条 |

负责人姓名保存当时快照。原成员改名、停用、降为只读或不再可分配时，已有负责人历史仍保留，界面提示重新分配；新分配必须通过服务器的当前成员资格检查。负责人目录只提供分配需要的最小成员资料，不扩大成员管理权限。

内部历史在打开详情时按需读取，列表只带次数及最近记录时间。历史不能由客户端整份替换、修改作者或伪造保存时间；达到200条时拒绝继续追加，不自动删除旧记录。记录次数表示内部追加次数，不能解释为向客户发送或成功送达的消息次数。

工作台及列表每60秒按当前界面时钟更新到期提示；这不是后台定时任务、邮件提醒或系统推送，也不会自动向客户发送消息。归档或人工判为无效后不再显示跟进提醒；已联系且仍有下次排期的有效询盘继续按排期提醒。打开列表会读取最新询盘，也可手动刷新；时钟更新不等于自动拉取其他成员刚保存的数据。

## 保存、冲突与只读成员

“保存跟进”一次保存本地改动的负责人、优先级、排期、有效性、处理备注，并可追加一条内部记录。服务器以该询盘自己的`revision`检查并发，在同一事务中保存，不影响网站草稿和公开版本。

每条询盘独立保留备注和全部跟进草稿，保存B不会清掉A的未保存输入。副本按登录账号隔离，旧版本仅有备注的缓存仍可恢复。离开前有输入保护，恢复后保存仍需核对原记录版本。维护实现使用inquiry-notes:<询盘ID>，旧单键只读回退，仅成功保存或明确放弃本条时清理。

发现服务器字段或历史变化时，本地输入保留并提示核对。可采用服务器字段、保留待新增文本，或核对后继续保留本地修改；没有核对前不能覆盖保存。请求结果不明且历史数量变化时，要先查看历史，避免把已经保存的内部记录再次追加。

管理员和编辑成员可处理询盘及导出；只读成员可浏览列表、详情、来源统计、负责人和内部历史，可筛选和刷新，不能改状态、修改跟进、追加记录或导出。询盘可见范围沿用现有角色权限，分配负责人不会改变哪些成员能查看。删除、清理和通知重试继续仅限管理员。服务器会再次核对当前角色和账号状态，界面禁用不替代服务端权限。

## 公开来源线索

公开页面只读取URL中的`utm_source`、`utm_medium`、`utm_campaign`，以及浏览器提供的外部引荐主机。落地页只保留纯`pathname`，不带查询串或片段。提交来源`sourcePath`仍是经过签名和实际页面引用检查的纯路径，与访客携带的来源线索分开。

同标签页通过`sessionStorage`最多保留30分钟的有限线索。普通站内导航沿用原来源和原到期时间；新显式活动参数或新外部引荐可覆盖旧线索，到期不再沿用。SPA中的`document.referrer`每文档只读取一次，避免站内换页反复重写首次来源页面。后台、API路径和私有预览不采集或读写该存储；组件不产生统计网络请求。

禁用`sessionStorage`时，当前URL仍可用于正常提交；同一文档可退回内存，完整页面重载后不保证保留先前线索。浏览器未提供引荐、参数不合规格或环境异常时，询盘仍可正常提交，来源按缺失口径显示。不要把来源缺失解释为直接访问。

本归因功能不保存完整URL、查询串、片段、IP、广告点击ID、搜索词`utm_term`、跨标签页标识或全访客浏览日志；不向外部统计服务发送数据。外部来源只接受受限域名，拒绝完整引荐URL、IP、端口、凭据及控制字符，排除本站主机。活动字段限制长度和类型，不接受访客提交的“已验证”、分类或采集时间；分类与记录时间由服务器生成。

首次公开提交固定来源快照。发生网络中断、无法确认接收时，使用原答案、原令牌和原来源重试；已持久接收的回执不会被重试请求改写来源，也不会新增第二条询盘或通知。原有Origin、令牌签名、时间、蜜罐、限流、产品/语言范围和事务保护保持生效。

所有来源参数都是“访客携带信息，未经验证”。`utm_source=google`不能证明来自真实广告，外部主机也不能证明访客身份或渠道效果；浏览器、隐私设置和人工构造参数都会影响数据。

## 来源显示与统计口径

来源显示按五类处理，其中具体来源与缺失记录分别保留：

| 显示 | 当前证据 |
| --- | --- |
| 具体来源或链接活动参数 | 新记录包含受限UTM或外部主机；优先显示`utm_source`，其次外部主机，没有来源名时显示活动参数方式 |
| 后台人工录入 | 仅对新记录中明确写有`origin:'manual'`的询盘使用 |
| 历史未采集 | 旧记录有表单或来源页面，但没有新增归因字段 |
| 来源未记录 | 旧记录既没有明确人工标识，也没有可用的来源页面/表单依据 |
| 来源未提供 | 新公开记录完成来源采集，但没有可用UTM或外部引荐信号；不推断为直接访问 |

统计面板默认折叠，展开后可选近7天、近30天或全部，分别按渠道/来源、提交来源页面及活动名称分组。近N天是过去N×24小时，以收到询盘的UTC时间比较，包含期间内已收记录；不是自然日，也不是页面访问量。近7/30天不纳入日期缺失的旧记录并显示排除数，全部期间可纳入并提示日期缺失。

统计基于当前已读取的全部询盘，与上方列表筛选独立；状态和人工有效性不会删除记录，表中分别显示收到、有效、无效、待判断的条数。活动名或页面缺失单独显示未记录，不把缺失当零。

没有访客总量、广告点击或采购结果作为分母，因此不提供转化率、真实投放效果或成交归因。有效/无效是内部人工判断，不能作为客户认证。访客携带参数可能被伪造，来源计数只适合辅助安排后续调查和跟进。

## CSV导出

“导出当前询盘”与列表搜索、状态、国家地区及跟进范围使用同一筛选规则。选择“我负责的”时只使用服务器已鉴权账号，客户端不能指定其他人的身份。统计面板的期间和维度不改变列表导出范围。

原14列顺序保持，末尾追加来源方式、三项UTM、外部主机、进入页面、来源记录UTC时间、未经验证声明、负责人、优先级、人工有效性、下次跟进UTC、内部记录次数及最近内部记录UTC。完整内部历史不进入CSV；历史可在询盘详情查看。

继续使用UTF-8 BOM、UTC日期和统一CSV引用，公式前缀文本加单引号，防止来源、活动名、负责人等内容在表格软件中执行公式。单次最多10000条。只读成员不能导出；下载不会自动发送到邮箱或第三方。

## 升级、资料保留与交付边界

跟进字段存放在询盘运行数据里。打开旧记录时，界面提供缺省值，保留原字段、备注、状态、来源页面和历史记录。系统不会用当前配置补猜旧记录的来源或人工标识。

询盘及内部历史仍不进入公开网站快照、整站模板和分发包。网站发布、切换公开版本和恢复草稿不会覆盖询盘。保留期限默认不清理，删除/清理仍沿用现有显式预览和确认流程；永久删除询盘也会删除该行内部历史，不能靠网站版本回退恢复。升级前保留实例备份。若需回退代码，应先在隔离副本验证兼容，保留最新数据库和媒体，不能用旧备份覆盖升级后新增的询盘。没有新增SQL迁移不自动保证旧程序能安全写新记录；旧界面也无法管理新增字段。

内部跟进记录保存在后台。向管理人员发送邮件通知时，使用站点配置的 SMTP 服务。
