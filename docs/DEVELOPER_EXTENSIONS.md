# 本地开发者扩展与高级布局

本功能使用已编译的本地源码扩展，不是在线插件市场。客户仍在同一Ant后台拖放组件和编辑结构化属性；增加或改变渲染实现需要开发者修改源码、验证并重新构建。JSON不选择模块路径、不安装npm、不执行表达式。客户自定义CSS/JS仍属于原来的可信管理员功能，权限和隔离边界没有被此扩展入口替代。

## 注册契约

- `src/extensions/registry.ts`：稳定namespace/type、名称、独立数据版本、可读版本、许可、props schema、默认值与纯数据迁移。示例类型为`studio/SpecificationTable`，当前数据v2，可读v1/v2。
- `src/extensions/render.tsx`：在扩展目录内注册实际React渲染。与网站统一ConfigProvider、组件外壳和样式编译共用；画布/模板/卡片/私有预览/公开站都走同一实现，不按行业分支渲染。
- `src/extensions/editor.tsx`：schema生成Ant字段；规格行提供增删、上下移和50行上限。复杂业务字段应在扩展目录加专属Ant控件，再接注册表；不要把React代码存进props。
- schema中`product`/`document`字段声明引用种类；`extensionReferences`提取，保存检查目标、发布要求选中目标、媒体删除保护和整站映射共用。示例产品ID与PDF URL会映射，规格值里的同名业务文字不会被误改。需要更多引用种类时，在该契约及统一引用/分发处一起实现并测试。
- `src/lib/component-contract.ts`集中已知类型和版本检查。新增本地类型须在注册表和扩展渲染映射两处完整注册，再跑验证；不要只加一个编辑按钮。保留默认值、字段与渲染的一致性。

Puck按类型生成的节点ID可包含namespace/type的分段斜线，仅组件节点接受此格式；页面、产品、媒体和区块记录ID仍用原严格白名单，节点不允许冒号、路径回退或原型键。CSS样式类名使用十六进制编码，手写选择器建议设置独立锚点别名。

示例数据：

```json
{"type":"studio/SpecificationTable","props":{"id":"spec-main","extensionVersion":2,"title":"Specifications","caption":"Synthetic example only","rows":[{"label":"Item","value":"Add verified customer information"}],"productId":"","fileUrl":""}}
```

规格名称最多120字符、值2000字符、标题160、说明500。所有内容作为纯文字渲染；空字符串是未选择的可选引用，不替用户编造产品参数。文字、行、关联产品和PDF可编辑；公共样式面板控制整个组件的尺寸、外观和三端布局。示例实现使用Ant表格。Ant列回调在客户端视图内部，RSC边界只传纯JSON；Puck iframe通过官方StyleProvider向真实画布文档注入动态变量，公开端保留SSR样式收集。锁定cssinjs2.1.2，不修改依赖源码。字号与文字颜色继承组件外壳，窄屏会折行。

v1曾使用`items:[{name,value}]`；当前迁移将其转为`rows:[{label,value}]`。渲染时只在内存归一化，不改原历史快照。编辑旧属性布局会先显示明确的“升级当前布局组件到草稿”入口，升级后才挂载Puck，防止默认新字段覆盖旧值。升级只改当前布局草稿；分发导入也在映射时归一化，预检后确认。未来版本和未知业务属性必须拒绝，不能用默认值吞掉。

## 兼容、升级与移除

协议15读取1–14和15；扩展还必须满足独立的type/extensionVersion可读范围，同协议号也不能跳过此检查。真实协议14双语关系fixture来自B实例公开导出，没有改低新数据版本数字。回退旧程序须使用升级前程序/配置/数据副本；不能让旧程序读取15完成数据回退。

未知节点可以保留在历史/草稿JSON，但未知布局不能挂载到Puck自动保存；可导出原始布局并返回管理页。未知/未来组件不能发布、复制分发或激活到公开指针。公开站遇到缺失的已发布实现会明确拒绝渲染，不能把节点悄悄删掉后仍当完整网站显示。开发者必须在升级前保留原镜像和完整备份。

在“设置→开发者扩展”检查草稿和保留历史引用，或管理员GET `/api/extensions`。接口只读，编辑/查看角色不能访问。扫描上限为50份历史、历史JSON16MiB和100000个遍历项；覆盖不全明确显示，不能据此认定可移除。引用次数包含未引用资产定义本身。保留历史仍依赖旧实现，应保留兼容渲染器或先制定历史归档方案；后台没有一键卸载源码。

整站包清单包含实际使用的本地组件版本与许可，导入仍先检查注册/属性/引用。不会自动安装缺失组件。新增扩展许可按本地开发合同记录；第三方依赖许可另见THIRD_PARTY_NOTICES.md，不能把整个依赖树称为同一许可证。

## 受控高级布局

在元素样式的“高级定位与裁切”可设置：正常文档流、relative、容器内absolute、sticky；top/right/bottom/left为-240至2400px或auto；z-index整数0–20；横纵位移各±480px；overflow为visible/hidden/clip/auto。声明式入口不支持fixed、任意CSS表达式或自定义断点。

绝对定位必须放在显式Container内，复用样式和令牌的最终值也检查此规则。绝对元素不撑高父容器，应给容器足够高度，并在手机端按需改为正常文档流、将距边设auto、位移归零。容器建立局部层叠上下文；仅使用新定位/位移的页面启用相应基础CSS，不全局改变旧客户自定义CSS的包含块。整页根和表单输入/提交样式不能直接脱离文档流。

sticky受最近滚动祖先、距上和父容器高度限制。overflow裁切也会影响sticky范围；隐藏/裁切不删除数据。有意叠放仍需检查可点击区域和键盘焦点。hover/focus/active沿用颜色、边框、圆角、阴影、透明度，新增有限位移；不允许交互时突然改变文档定位方式。

断点仍为桌面→平板≤1024→手机≤700，清除覆盖恢复继承。画布宽度不是站点自定义断点。站点级任意断点需要另做整体响应式迁移，当前没有散落数字式配置入口。

画布“检查布局”读取当前设备实际DOM，提示左右越界、absolute超出父容器、可能覆盖交互控件，最多30项；不自动修正有意叠放。切设备、修改或滚动后重新检查，还要看公开页面；此检查不是完整无障碍或所有滚动状态证明。

## 开发验证

执行typecheck、单元/服务测试、生产构建与`test:http`。关键新增测试在extensions.test.ts、extensions-service.test.ts和s13-http.ts；C容器组合验证另见acceptance-c.cjs及阶段报告。扩展升级必须核对模板捕获/复制、当前卡片上下文、PDF/产品引用与包映射、v1迁移、未知类型/未来版本和移除检查。不要修改依赖源码或在客户后台提供服务端代码执行入口。
