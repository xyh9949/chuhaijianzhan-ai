# 外部AI连接与网站助手 Skill

应用0.31.1；历史增量按各节标注版本理解。文章、产品文案及SEO操作见[内容与搜索指南](EXTERNAL_AI_CONTENT.md)。原有七个设计工具仍保留，扩展权限独立选择。入口：**站点设置 → AI服务 → 外部AI连接**。管理员可以把自己使用的AI客户端连接到这个网站，读取授权内容、生成原生设计方案、查看真实预览并继续调整。网站仍由原编辑器自由拖拽维护。

## 连接方式

1. 点击**创建AI连接**，填写容易识别的名称，选择只读或允许生成方案，指定整个网站或页面范围，以及1–365天有效期。
2. 保存创建时显示的密钥。明文只出现一次，关闭弹窗后不能再查看；丢失时撤销该连接并重新创建。
3. 在支持 Streamable HTTP 和自定义请求头的AI客户端中，使用设置页展示的 `/api/mcp` 地址，把密钥保存在客户端私密配置的 `Authorization: Bearer …` 中。
4. 下载设置页提供的 Skill，将 `SKILL.md` 放入客户端的 `form-studio-site-design` 技能目录。技能目录和加载方式以客户端自己的说明为准。

这是独立密钥连接，未实现OAuth浏览器授权或自动客户端注册。不能据此声称所有AI客户端都能直接连接。远程服务应使用HTTPS；`127.0.0.1` 只对当前电脑可访问，云端AI客户端不能通过这个地址访问你的电脑。

只支持本地命令的客户端可使用项目附带的标准stdio桥接器。执行命令为 `node` 加 `scripts/mcp-bridge.mjs` 的绝对路径，客户端私密环境中设置：

| 环境变量 | 内容 |
| --- | --- |
| `FORM_STUDIO_MCP_URL` | 本站完整MCP地址，例如 `http://127.0.0.1:3200/api/mcp` |
| `FORM_STUDIO_MCP_TOKEN` | 创建时保存的连接密钥 |

脚本需要项目依赖已安装。不要把实际密钥放进命令行、聊天、公开示例、网站内容或源码仓库。界面中的连接列表只显示尾号、范围、到期时间和最近使用时间，撤销后立即失效。

## 从一句话到整个网站

例如：“我们面向海外工程商，首页需要更专业。保留Logo和真实产品，页眉更简洁，产品入口清楚，各页字体和留白统一，手机也方便浏览。”

外部AI先读取站点概览和真实可编辑能力，再获取目标范围的原生结构。它用自己配置的模型理解业务目标并提交原生操作，网站不会为普通设计操作再调用一次站内模型。

方案保存在创建连接的管理员账号下。外部AI得到同一方案的前后预览、影响范围和状态；你登录后台后查看真实电脑、平板、手机效果，再反馈“保留产品布局，只让页脚更紧凑”。外部AI基于该候选继续提交，保留原始修改前版本和累计修改后版本。

需要应用时，AI返回类似 `/admin?externalDesign=方案标识#global-design` 的审核地址。后台只读取该账号的候选，不会因打开链接、刷新、恢复登录或模型传入“已确认”而写草稿。你在真实预览里按**确认应用到网站草稿**；已应用方案可通过同一入口按**撤销本次整站设计**。发布仍走原发布管理。

有未提交的代码或设计要求时，沿用原离开保护，先保存、保留或继续编辑。无权限、已过期或找不到的方案会显示具体问题，不用实时草稿冒充原候选。

## 权限和边界

- 基础设计权限是**读取网站**与可选的**生成设计方案**；内容、SEO、模板和设计约定另按对应范围授权。不包含机器直接应用、撤销、发布、运行脚本、读取询盘、账号或站内AI密钥。
- 指定页面的连接不能修改全站页眉页脚、导航和默认风格。整站设计还要选择完整页面范围；既有锁定、文案保护、独立布局和局部覆盖继续生效。
- 修改全站区域时，AI需分页取得全部当前页面ID作为范围，实际操作仍只改用户指定正文和区域。统一效果按真实继承和局部覆盖说明；预览打不开时交付入口和未验证项，旧图不能冒充当前候选效果。
- 负责人降权、停用，或连接到期/撤销后，后续访问立即拒绝。不同连接的候选读取与继续调整也受到隔离。
- 采用和撤销继续使用原事务、版本和外部引用保护。发生冲突时保留后续手工修改，不覆盖当前业务资料。
- 当前支持真实原生方案、预览与用户后台确认；没有外部自动发布、截图视觉评分、自动付费修正或所有客户端兼容保证。

完整设计限制、候选时间和撤销范围见[AI整站设计](AI_SITE_DESIGN.md)。本机确定模型或SDK客户端回归只证明协议和软件流程，真实模型的审美、业务理解及用户满意度仍需真实任务评估。

## 协议与维护

| MCP工具 | 用途 |
| --- | --- |
| `site_overview` | 按`offset/limit`分页读取授权页面、当前revision及权限；全站区域需取全页面ID |
| `site_capabilities` | 按需读取原生操作契约、限制及不支持能力 |
| `site_design_context` | 传`expectedRevision/instruction/targets/preserveText`；可用`baseDesignId`读累计候选，用`detailPageId`读取目标页安全现值 |
| `site_design_propose` | 提交`{requestId, request, proposal}`，生成私有候选；`proposal`最多32组原生操作，网站草稿保持 |
| `site_design_status` | 以`designId`查询本连接候选、预览入口及真实采用/撤销状态 |
| `site_design_review` | 传`designId`和`action: apply/undo`，取得用户后台审核链接，不代替确认 |

同一次断线请求使用相同requestId和相同内容；新一轮调整用新requestId，并在request中带原baseDesignId。已成功的提案重试读取原冻结回执，不因后来替换图片引用而重新执行；当前范围、撤权和私有约定权限仍复核，异体请求仍返回409。指定页面或过期连接不能借此扩大授权；只读连接不提供提案工具。图片、按钮和复杂样式需要详情时再按页读取，不能从摘要猜素材或绑定。单页详情的imageLibraryTotal与图片明细共用授权集合；最多展示24项不代表总数就是24，限定页连接不会得到未授权的全库图片总量。外部上下文不包含私有写作指引、未确认事实、账号、询盘或模型凭据。

MCP传输采用官方 TypeScript SDK 固定版1.32.2，提供无会话的Streamable HTTP和JSON响应，验收协议为2025-11-25。每个HTTP请求独立建立SDK实例；不使用自写JSON-RPC分发器冒充MCP。当前不提供常驻SSE订阅、跨请求取消或流恢复，断线不等于取消；重连后按业务请求标识或候选标识核对结果。

升级后应验证：初始化/工具发现、Origin和独立凭据、范围与负责人权限变化、原生候选校验、断线幂等、真实预览、继续调整、后台审核深链及撤销冲突。需要备份客户数据库、媒体、固定密钥和配置，不能用旧数据库覆盖后续业务资料。

机器凭据及请求幂等记录随实例私有数据库备份。切换程序版本前，应在隔离副本核对旧凭据的页面范围、吊销和候选权限。[升级和回退](../DEPLOYMENT.md#升级和回退)

传输拒绝非配置Origin/Host，密钥只能出现在Authorization中；请求体最多512KiB，响应投影最多512KiB。401需检查连接期限、吊销和负责人状态，403需检查范围与实际连接地址，409需读取当前revision或更换被用于不同请求的requestId，410表示候选/回执已过期。GET/DELETE返回405属于本批无会话MCP模式，不表示应绕过鉴权或改用后台Cookie接口。

官方依据：[MCP传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)、[MCP取消语义](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation)、[官方SDK 1.32.2发布信息](https://registry.npmjs.org/@modelcontextprotocol/sdk/1.32.2)、[固定版本传输实现](https://github.com/modelcontextprotocol/typescript-sdk/blob/3b73021a0a2272c0c04c3917bcdb03398b3ec63f/src/server/webStandardStreamableHttp.ts)、[Agent Skills格式](https://agentskills.io/specification)。Next适配依据项目锁定版本的本地Route Handler文档与SDK原生Request/Response传输实现；没有把它称为官方Next专用集成包。

## 内容和 SEO 权限的兼容性

从只支持外部设计的版本升级时，既有凭据的内容和 SEO 权限默认留空。先验证旧连接原有权限，再用单独凭据验证新增加的内容审核流程。

## 挑选设计范围

0.24的 `site_design_select` 从原方案实际 `selectionUnits` 派生新范围预览，继续原read/propose权限。必须跟踪新designId并由用户审核，原整份方案没有被采用。后台选取外部来源时也继承本连接归属，来源状态可查看最近最多20个直接派生方案；不据此推断完整历史。具体规则见[按范围采用指南](AI_DESIGN_SELECTION.md)。

## 详情模板设计（0.25）

在创建连接时另选“允许访问详情模板”，指定全部或具体产品/栏目模板，并明确可使用的产品和内容范围。旧连接默认模板范围为空，页面全站授权不自动扩大。read允许读取与审核，propose才允许提交模板候选；模板预览授权不等于能改产品或文章。

新增 `site_template_overview/context/propose/status/review` 五个工具，完整权限时合计23个；未开启模板时保持原18个，模板只读不提供propose。流程、标准化请求、真实命中/强制布局样本区别和升级/回退见[详情模板指南](AI_DETAIL_DESIGN.md)。模型使用客户端配置，站内不二次调用；仅本人后台确认后保存草稿，继续原生拖拽，公开更新另行发布。

## 设计约定读取（0.28）

新增可选 `design-guidance:read`，默认不勾选且必须同时有基础read。它只授权读取全站设计参考文字，独立于页面范围；不扩展其它页面、事实、产品或设置。具备时才发现 `site_design_guidance`；旧完整23工具不变，额外授权后多1工具。整站/模板上下文的标准化请求带 `guidanceRevision`，新提交须原样带回，版本变化需重读；已成功同ID请求仍先恢复回执，不重复生成。

约定暂停时不会自动加入新设计上下文；已获得只读权限的连接仍能主动读取已保存内容，如需停止外部读取应撤销连接。约定正文和模型可能转述它的摘要都受读取权限保护，撤权后不能从旧guided候选、续调、派生或幂等回执绕过。外部工具不能保存或自动学习偏好；长期要求由用户后台明确确认。详见[设计约定](AI_DESIGN_GUIDANCE.md)。

## 页面内区块和结构分组按需采用（0.29–0.30）

`site_design_status` 保留原 `selectionUnits`，另返回 `sectionUnits`。整页、页眉/页脚与风格的旧ID和含义保持。子单位 `kind:"section"`、`area:"page"`，`pageIds` 只标明所属页面，`parentId` 指向原整页单位；`nodeIds` 是该组修改前后根区块的并集，可包含只在修改前存在的已删除根。不能因某个根在after里找不到就丢掉它。只有服务器返回的单位ID可以提交，不能把nodeIds或某条changes的序号当成选择ID。

继续使用原 `site_design_select({requestId,designId,expectedRevision,unitIds})`，没有新工具或额外写权限。选择整页时不再同时选它的子单位；明确全选整个方案仍只提交原selectionUnits。0.31.1用户挑选区块时，即使该页区块选满也保留section IDs，不能自动扩成page ID；只有明确整页采用才扩大范围。每次最多103个单位，按实际能力和返回的限制拆分需求，不能静默丢弃选择。有限页面连接只得到被授权页面的整页及根区块单位，不因新增元数据获得其他页面、模板、产品或私有设计约定。

0.30可将根区块新增、删除、重排和后代跨根迁移按结构依赖合成原子组。例如旧介绍被新展示区替换，或内容移入另一根区块时，相关根可能必须一起采用；客户端不能再拆开其中一个根。每个组包含受影响根的完整子树，所需动态卡片和菜单由原生服务核对引用并带入。页面共同样式/显隐、无法安全核对的旧结构或超过预算时，仍会在原页面单位中提供sectionSelectionUnavailableReason并保留整页选择。它不是任意逐节点、任意层级的采用功能。

稳定同序的独立单根继续使用0.29的 `section:<32位hash>`；结构组使用 `section:g1:<32位hash>`。这些ID仍是服务器生成的不透明标识，不是客户端需要拼接或推算的格式。旧缓存的单根若已属于更大依赖组，应重新读取status，让用户核对新的实际范围；不能自动把旧选择扩成更大组。历史 `selection.unitIds` 和 `selectionPreviews.unitIds` 保留当时提交的来源ID，不改写历史回执。

单个方案最多200组，每页修改前后各最多100个根，一组的前后根并集最多200个；超限不截断分组。先向用户说明实际范围，再生成新的真实预览，用户在后台确认后才保存。新designId需继续跟踪，原候选状态保持，偏好隐私溯源、负责人/吊销检查和同请求幂等规则仍适用。成功请求仍按原requestId和原内容重试，不能因来源分组算法更新或源方案已删除而重新生成。

本批没有新增站内模型调用、发布或机器直接确认权限；新候选仍使用普通原生页面和卡片数据，后续继续在原编辑器维护。数据库17、公开快照20与renderer20保持。旧客户端可继续只读取selectionUnits；要选择区块组应按本次服务器的能力说明和sectionUnits读取，不依赖本地硬编码组件名或旧分组假设。

## 稳定区块里的细项选择（0.31）

`site_design_status` 在保留原整页和根区块单位的同时，另返回 `detailUnits`。细项 `kind:"detail"`、`area:"page"`，`parentId` 指向所属section单位，`rootId` 标明该section的唯一顶层根，`nodeIds` 描述实际选择的完整子树。仍使用原 `site_design_select` 的 `unitIds` 传单位ID，不新增工具、输入字段或权限。有限页面连接仅获得可见单根section下、页面与根归属一致的细项；g1结构组不会被投影成可拆父项。

例如首屏容器本身不变、只有标题和说明改变时，可以只选标题。父类型、排除插槽后的自身属性、插槽签名以及直接子节点身份和顺序保持，服务器才继续下钻；最近出现结构或属性变化的父树会作为完整原子项。内部新增或重排的布局可能整体可选，但不能再拆开其中一项。g1根结构组保持整体选择。这不提供单个样式属性或任意未列出节点的选择。

只提交服务器本次给出的细项ID。细项使用独立 `detail:d1:<32位hash>`，不复用原section或g1的ID，仍不能在客户端自行拼接。整页与后代、父section与细项、互相重叠的子树不能混选。选中某根全部列出的细项时也保留这些细项ID，不能自动替换成整根：未列出的兄弟内容可能已有人工修改。默认整页/整section单位的含义不变，旧ID与历史回执不重解释。单个候选另最多200细项；超预算完整回退该根section并通过 `sectionUnits[].detailSelectionUnavailableReason` 说明，不截断可选项。每次提交仍最多103项，超过时由用户决定缩小范围还是采用整根。

细项组合仍建立新的普通原生候选，不调用模型、不写草稿；读取新designId的真实预览，再由用户后台确认。后续手改、锁定、依赖、来源范围、同连接归属、guidance隐私溯源和幂等回执仍逐次复核。旧客户端可以忽略新增数组继续选择整页或根区块；新客户端不能根据旧本地假设推算可选细项。
