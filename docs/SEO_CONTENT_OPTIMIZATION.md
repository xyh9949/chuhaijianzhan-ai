# 按搜索数据完善正文

## 使用与覆盖范围

后台“搜索优化”中可选择一条产品、文章或普通页面，点击“完善正文”。已同步的 Google Search Console 搜索行也有“按此搜索词完善正文”。不会点击即调用模型；用户先选择原文字段、自己的已保存报告和具体数据行、可选站内链接，再明确生成。

- 产品写入原生 `detailContent` 长详情；保留原图、原链接和原文。
- 文章选择明确的多行正文字段，保存原生 `richTextFields`，同步纯文字镜像，原编辑器可继续排版。
- 普通页面只读取静态 Heading/Text/RichText，新增独立的原生 RichText 区块，可拖拽和改响应式样式。动态绑定、列表、同步区块不会冒充静态原文发送；真实页面预览仍展示实际布局。详情模板用具体记录正文或既有 AI 详情设计入口，不扁平覆盖模板。
- 正文补缺、买家 FAQ、站内链接、搜索标题、搜索描述分别勾选；元数据默认不选。正文与 FAQ 都为追加，不替换整篇文章。

AI 由用户在“站点设置 → AI服务”配置。每次生成只发一次模型请求，失败不自动重试；`seo-content` 使用记录由统一计量模块登记。这里没有免费内置模型或代配置接口。

## 证据与设计边界

API 支持最多 5 份本人报告、每份最多 20 行，界面每次选择一份报告的具体行。GSC 行必须匹配当前目标真实网址；关键词报告语言必须匹配内容语言。发送给模型的只有明确勾选行，保留零值、国家、语言、设备、日期、时区、来源、模拟标记及部分覆盖说明，不把缺失值当零。

不选报告也能按现有资料完善文字，但明确标注“非真实搜索需求证据”。模型只能引用给定报告行。站内链接只能从用户明确选择的同语言真实目标编译，模型不给 URL，也不能输出 HTML、脚本或任意链接。当前实现的事实依据是有限的已保存资料，并非自动验证所有商业声明；潜在数字、认证等声明会给出核对提示，未知事实由 `missingFacts` 明列，不能因此承诺排名或收录。

生成时冻结原文、字段和布局、语言配置、所选报告行、所选链接目标。采用前再次检查；原文、报告或目标路径被修改后旧候选不能覆盖新工作。不会自动同步搜索报告、发外网探测或发布站点。

## 预览、采用、撤销

生成结果为本人私有候选；管理员只能看自己的记录。结果包含原文和生成文档、逐组选择、来源数据、真实页面前后预览。`after?groups=body,links` 与当前选择严格一致，不把未选 FAQ 或元数据展示为将采用的内容。编辑生成要求后，旧候选必须重新生成或从历史记录明确恢复。

确认采用才写工作区草稿；公开版本指针不变。重复相同采用不重复追加，不能借旧候选扩大范围。采用后仍在原编辑器可编辑。

- 候选未采用有效期 40 分钟；采用后保留 7 天撤销依据。
- 产品和文章撤销只恢复本次触及字段，保留其他手改；本次正文后来改过则拒绝危险撤销。
- 普通页面撤销只删本次仍未改的新增区块；保留原布局和之后新增的人工区块，生成区块被改或移入其他容器则阻止删除。
- 搜索标题与描述只恢复已勾选字段；后改同样受保护。
- 请求体或路由参数异步读完后重新核对会话，写事务内再次核对权限。模型请求被合法接受后退出登录可保留本人私有结果，权限降级或停用仍阻断完成及采用。

每人私有候选总量最多 100 条、生成中最多 30 条、总载荷 10 MiB。模型前预留 1 MiB 输出容量，失败移除预留，成功输出或撤销依据超限会拒绝，不以付费生成后才发现空间不足代替预留。

## 发布内链复核接口

`seoContentLinkPublicationErrors(candidate, draft, active)` 是独立纯函数，供统一发布器调用。扫描原生产品长详情、文章富文、Puck RichText、同步区块、模板的 literal href；只对草稿或上一公开快照中可由真实路由解析的本站地址建立依赖。目标或必要模板未包含到候选公开快照时报告错误。

literal href 不包含对象 ID，故同一路径被不同 ID 的合法页面承接时允许；SEO 提案采用前的冻结 ID 检查仍独立保留。同源地址只去查询和锚点，不解码点段、斜线，不联网。普通未知 URL 及外链沿原规则，不伪称全站死链探测。

## 验证

`tests/seo-content.test.ts` 覆盖本地 mock 模型、精确报告行、零值及来源、原生组合、真实子集预览、私有权限、后改保护、撤销、会话边界和容量预留。`tests/seo-content-links.test.ts` 覆盖路径归一化、模板依赖、公开旧目标、语言、同路径异 ID 以及各富文入口。所有数据库为临时 SQLite，模型为本机合成服务，不读正式库、不调用真实模型。

`tests/ui/seo-content.spec.ts` 为隔离站点浏览器流程：真实选择报告行 → 生成 → 子集真实预览 → 手机宽度检查 → 明确采用 → 撤销；复核原图、原链接、未选搜索字段及公开版本。由共享 UI mock 注册 `SEO_CONTENT_OPTIMIZATION` 协议后运行，不把未运行的 spec 当作已验收结果。
