# AI设计方案按范围采用

适用应用0.31.0（原整页选择自0.24提供），入口：**网站页面 / 全站设计 → AI设计整个网站 → 逐页看效果与继续调整**。沿用用户配置的模型；浏览和挑选已有方案不调用模型。0.29增加[页面内区块挑选](AI_DESIGN_SECTIONS.md)，0.30扩展[关联结构组](AI_STRUCTURAL_SECTIONS.md)，0.31增加[内部子树挑选](AI_DESIGN_DETAILS.md)，原页面/头尾/风格单位保持。

## 普通用户怎样用

1. 先生成或打开一份尚未采用的AI整站方案。
2. 展开 **只采用部分修改**。选择满意的页面、全站页眉与导航、全站页脚与导航，或全站默认风格。选项只列本方案实际改变的范围。
3. 点击 **预览选中修改**。系统新建一份范围方案，保留原方案。此时不保存网站，也不使用模型额度。
4. 查看新的前后真实预览。它只组合本次选择的布局，卡片、嵌套区块和菜单随真实引用带入；原本未选的页面和风格保持。
5. 满意后点击 **确认应用到网站草稿**。保存后仍能在原拖拽编辑器继续修改，公开网站仍使用原发布流程。
6. 不合适时回看原方案重新挑选，或在当前范围用自然语言继续调整；新的模型生成才使用用户的AI服务。已采用方案可在七天内按实际修改范围安全撤销。

更改勾选后，屏幕上的旧方案只供参考，确认按钮会禁用，必须先准备选中范围的真实预览。未预览选择、描述和追问沿用原本地草稿保护；恢复输入不会自动调用模型或保存网站。

## 可以选择到什么程度

| 单位 | 包含内容 | 保持内容 |
| --- | --- | --- |
| 单个页面 | 该页面的整份排版修改及其实际需要的新独立动态卡片/区块 | 未选页面、全站风格和未选头尾 |
| 全站页眉与导航 | 页眉布局、关联导航和所需独立资源 | 页脚、页面正文、各页已有独立显隐 |
| 全站页脚与导航 | 页脚布局、关联导航和所需独立资源 | 页眉、页面正文、各页已有独立显隐 |
| 全站默认风格 | 本方案修改的默认字体、颜色和间距 | 页面已有局部覆盖、其他主题字段与未选布局 |

这是按可独立保存的设计范围选择，不是对累积修改说明逐条勾选。0.29可进一步选择独立页面根区块；0.30支持增删/重排和跨根迁移按依赖成组，完整嵌套和资源一起核对。共同设置等不能拆分时保留整页，任意后代节点拆分仍未开放。条件详情模板AI编辑已在0.25单独提供，见[模板指南](AI_DETAIL_DESIGN.md)。

## 并发、依赖和撤销

派生范围方案以当前工作区建立新基线，保留原候选及后来无关工作。所选页面、头尾或相关原卡片/菜单已经被人修改时会拒绝；全站区域还检查当前锁定内容、默认头尾固化的企业资料与语言。不会拿旧整站快照覆盖新工作。

新方案继续沿原事务采用/撤销；选后又有工作区变更时需重读并重新预览。撤销只恢复实际采用的页面、字段和独立资产，后续手工修改或新引用会阻止危险撤回。待确认期限不超过来源候选的40分钟窗口，最多连续挑选6次；采用后保留7天撤销窗口，仍需无冲突。

## 外部AI与MCP

原网站设计的read/propose及页面范围继续生效，没有增加内容或SEO读取权限。具propose的连接多一个工具：

`site_design_select({requestId, designId, expectedRevision, unitIds})`

先从 `site_design_status` 读取服务器返回的 `selectionUnits`、`sectionUnits`或0.31的`detailUnits`，按实际需求选单位ID；整页、所属整块与内部子树不能重复提交，内部全选不能自动扩成整块。用当前草稿revision和新requestId提交；同一请求断线重查保持requestId与内容相同。它只建立新私有候选，不调用站内模型、不保存、不发布。

必须继续跟踪返回的**新designId**，再用 `site_design_review` 返回该新方案的后台审核链接。原方案仍是未采用状态；`selectionPreviews`列出本连接最近最多20个直接派生方案及真实状态，不能把它当完整历史或把任一子方案采用称为原整份方案已采用。在浏览器挑选外部来源方案时，同连接归属也会继承，其他连接不能读取它。

## 升级和回退

原0.24批次保持SQL13；当前0.31的SQL17来自后续其他能力，renderer/snapshot20、minReadable1保持。范围候选的执行差异继续使用原页面/主题/布局/独立资产结构；旧候选读取时补投影范围单位，不重写客户资料。

切换应用版本前保留数据库、媒体、固定密钥和原版本源码。在隔离副本依次验证旧候选的读取、预览、采用和撤销。草稿中已采用的设计应通过对应候选的撤销入口处理。[升级和回退](../DEPLOYMENT.md#升级和回退)
