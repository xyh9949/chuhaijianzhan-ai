# 多语言内容与网址

网站内容按语言独立建档，后台仍为中文。每条页面/产品/独立内容的语言、翻译组、核对状态在其信息表单维护；同类同组每语言最多一条，独立内容组不能跨模型。模型字段结构共用，正文值、SEO、网址和发布分别维护。

1. 在站点设置→语言与地区增加标准语言代码和显示名称并保存草稿（最多10种）。配置不会翻译内容。
2. 从翻译组总览复制到目标语言。新记录是待核对草稿，有独立节点ID；原文和译文建立同组身份。复制的CSS保留并重映射，JS关闭。缺译关系清空并提示，找到同组目标译文才自动对应；产品型号必须唯一。
3. 编辑正文、标题、SEO和菜单/表单文案，再明确选择“已编辑并明确核对译文”。待核对记录不能发布，不能通过清空状态绕过。
4. 静态页保存实际完整地址，例如/de/about；产品和独立记录只保存最后标识，详情地址由共享默认详情入口加语言前缀生成。默认语言无前缀，其余语言使用小写代码目录，例如/de/products/stuhl。默认详情模板本身不能作为某个语言记录复制，可用带语言条件的资源布局覆盖。
5. 各导航元素和全站默认头尾可选择各语言菜单；没有映射时不会自动当成原语言菜单。表单文案在独立表单定义维护，再将对应表单放到对应语言页面/条件模板。
6. 添加“语言切换器”，仅切换当前页面/产品/内容的同组记录。缺译可隐藏或禁用，不跳到无关首页。公开只出现已发布译文，鉴权预览可看草稿。查询列表在筛选和分页前按当前语言隔离，控件名称可按语言覆盖。
7. 发布时勾选具体语言对象；首次启用语言还需选择公开设置。建立组也会更改原文元数据，需核对是否一并选择。全部模板/菜单/表单仍各自作为明确整套范围，不会自动把所有译文上线。

如果先发布译文内页，默认页眉站名和面包屑先链接到已发布的默认首页。发布该语言首页后，同一入口会切换到对应语言首页。草稿预览与发布范围预览各自在自己的内容范围内采用同样规则。

公开 HTML 文档标注该网址的实际语言。SEO 内链诊断读取当前语言实际显示的页眉、页脚和菜单，也识别只有自链接的孤立页面。

公开canonical自指；hreflang只包含同组且实际可索引的公开入口。筛选和分页不会猜测跨语言页码映射。sitemap包含实际公开语言URL。询盘语言由验证后的来源页面决定，产品选项和提交校验都限定同语言；后台与CSV保留收到时语言，旧记录未采集显示“未记录”，不会用当前默认语言补猜。

更换默认语言必须使用“检查默认语言迁移”：准备该语言首页→预检网址变化和旧址占用→明确确认不能生成跳转的旧地址→应用到草稿。原记录固定为原语言，导航映射随之迁移；发布需明确包括设置、受影响记录/页面和相关布局。旧根地址被新语言占用时不能同时301跳走。预检绑定草稿修订和公开版本，变化后重新检查。外部链接及自定义程序仍需人工核对。

历史版本切换恢复整套当时语言路由，不回滚询盘。只恢复历史内容到当前草稿时，保留历史正文语言，并按当前默认语言重算选中静态路径和已知链接/菜单；需要历史原地址时显式包含历史语言设置，核对其他草稿依赖。跨默认语言恢复自定义代码需同时恢复设置，避免程序网址被猜测改写。

整站合并保留目标站默认语言和品牌；来源语言缺失时，必须显式勾选合并语言配置。语言前缀位于包目录前，翻译组按内容种类和包命名空间映射，不与目标同名组混合。改动只进入草稿；发布新语言仍需选择设置。新协议14读取1–13；升级前保留原镜像、配置和完整备份，旧程序不能读取14来完成数据回退。
