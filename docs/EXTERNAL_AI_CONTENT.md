# 外部AI创作、产品介绍与SEO审核

适用应用0.23.0。**站点设置 → AI服务 → 外部AI连接**负责连接和授权；后台的内容审核、产品管理、内容管理和搜索优化继续使用现有风格及编辑器。用户选择自己的外部AI客户端和模型，本功能不要求启用站内模型，也不为外部候选再调用一次站内模型。

## 普通用户如何使用

1. 管理员创建新的AI连接，明确允许“文案创作”或“搜索优化”，选择产品、文章和页面范围。旧连接仍保持旧权限，想增加能力需要新建连接。
2. 在自己的AI客户端配置本站MCP地址和私密Bearer密钥，下载“网站助手 Skill”。密钥只保存在客户端私密配置，不能放到聊天、网站内容或公开命令行。
3. 对AI说明具体需求，例如“依据这款产品的实际材质写一段简洁介绍，不增加认证与交期”，或“为经销商写一篇选型文章，参考这两个产品，保留已有图片”。AI先读取授权资料，再准备候选。
4. 打开AI返回的后台审核入口。文案审核按候选实际富文本展示原文和建议排版，支持文字增删对照与逐项选择；这是内容排版预览，完整详情页效果在保存后通过原编辑器预览。SEO审核展示前后搜索标题、介绍、依据，以及有独立路由时的真实页面预览。
5. 核对后亲自点击确认保存。它只写入网站草稿，公开网站仍要在发布管理确认。保存后的文章和产品可以直接进入原编辑器继续修改。
6. 不满意时把具体反馈告诉外部AI，基于本次候选继续调整后重新核对；已保存内容可以从同一审核入口撤销，后续人工修改或引用造成冲突时会保留现有资料。

新建产品的名称、型号、分类和材质应来自用户提供的资料。系统不会根据一段营销要求猜出真实参数。新文章需选择已有内容栏目和其可写字段；列为待核对的事实应补齐后再发布。

## 连接权限

| 权限 | 能做的事 | 不能做的事 |
| --- | --- | --- |
| 读取网站 / 生成设计方案 | 原有网站、页眉页脚和页面设计流程 | 自动增加产品、文章或SEO权限 |
| 读取文案资料 / 生成文案候选 | 读取授权产品、栏目和文字，准备文章及介绍 | 直接保存、发布，读取询盘、账号或密钥 |
| 读取搜索资料 / 生成SEO候选 | 读取授权目标和已保存报告，准备搜索标题与介绍 | 自动连接Google、同步报告、调用付费关键词接口 |

产品与文章分别指定范围：整类授权包含允许的新建任务；具体ID只授权已有记录；空范围不开放该类资料。SEO页面沿用页面范围，产品和内容沿用各自记录范围。工具发现与调用还会重新检查负责人角色、账号状态、凭据期限和撤销状态。

候选由创建连接的管理员账号持有。外部AI只能查询本连接候选；后台审核需创建者登录。新权限必须明确选中，0.22的设计连接升级后不会悄悄扩大读取范围。

## 文案闭环

| 工具 | 用途 |
| --- | --- |
| `site_content_overview` | 分页读取授权产品、内容栏目与已有记录 |
| `site_content_capabilities` | 获取服务器支持的字段、任务、富文本节点和限制 |
| `site_content_context` | 获取目标真实原值、标准化请求和可引用的已确认事实 |
| `site_content_propose` | 提交外部模型生成的内容，保存私有候选，草稿保持 |
| `site_content_status` | 以`candidateId`核对状态、期限、字段和审核入口 |
| `site_content_review` | 以`candidateId`与`action: apply/undo`返回后台审核地址 |

后台入口形如`/admin?externalContent=候选标识#ai-content-review`。精确的请求结构以当前工具schema、能力和上下文为准，文档不维护另一份可漂移的接口定义。

原生富文本保留正文排版及编辑能力，不接受任意HTML或脚本。已有图片、链接和不在本次选择内的字段保留；格式或引用不合法时拒绝候选。纯文字产品介绍与富文本文章有不同的长度及格式限制，按上下文处理。

应用时浏览器提交`expectedRevision`与`selectedKeys`；服务端重新核对候选、原始资料、当前版本和真实原值。现有记录采用原生写作回执登记实际保存字段；新建记录使用独立创建回执，防止“撤销”遗留半条文章或删除后来添加的资料。继续调整保留最初持久化基线，上一版候选不会变成真实原文。

“继续自由编辑”只传递记录定位，重新打开已保存的原生表单。浏览器存在另一份恢复草稿时先保留它，处理后再打开目标记录；不会用服务器回包覆盖尚未保存的输入。原编辑器仍有必填校验、图片上传保护、富文本校验和发布检查。

## SEO闭环

| 工具 | 用途 |
| --- | --- |
| `site_seo_overview` | 分页获取授权目标与支持字段 |
| `site_seo_context` | 获取目标搜索字段、有限诊断、正文依据、可选已缓存报告摘要与所选报告口径 |
| `site_seo_propose` | 提交外部AI准备的标题、介绍和说明，生成原生SEO候选 |
| `site_seo_status` | 以`proposalId`查看建议、依据、真实预览与状态 |
| `site_seo_review` | 以`proposalId`与`action: apply/undo`返回后台预览确认入口 |

后台入口形如`/admin?externalSeo=建议标识#seo`，沿用已有搜索优化弹窗及原生应用/撤销服务。即使没有启用站内AI或配置搜索接口，也能审核已经准备好的外部候选。已打开的手动编辑弹窗不会被新链接替换；候选采用或撤销后，之前未提交的手动输入仍保留。

SEO候选只修改搜索标题和介绍。真实预览使用候选的前后版本；尚未设置独立详情路由时明确显示限制，不以当前草稿冒充候选页面。Google可能改写标题与摘要，搜索展示示意不保证真实排名或收录。

搜索数据仍由用户在后台使用自己配置的接口主动获取。已保存报告随日期、时区、地区、语言、设备和覆盖范围展示；历史连接报告、人工导入与模拟报告保留标记。缺少数据时说明缺口，不用模型估算的数字冒充Google或关键词供应商数据。

## 确认、撤销与故障处理

待确认候选有效40分钟，已采用的撤销入口有效7天。期限内也会检查后续人工修改和引用；页面不承诺一定可无冲突撤销。文案生成要求上下文返回的草稿版本与写作资料版本均保持，避免将旧输出套用到新事实。

打开链接、模型输出“已确认”或聊天同意，都不保存草稿。MCP不提供直接采用、撤销或发布；`review`只返回入口。用户在后台按按钮后，服务器成功回执或后续`status`确认才能报告操作完成。

同一次提交断线时使用相同requestId及相同内容重查或重试，不创建重复候选。新一轮调整用新requestId并附上一候选标识。出现409冲突先读取最新状态，过期候选重新准备，不能改用旧整站快照覆盖。新建记录的撤销还需确认没有后续修改或新增引用，必要时在原编辑器手工调整。

故障时不自动调用模型、不自动重送付费请求、不自动发布。浏览器审核错误会保留候选并说明原因；连接失败需检查客户端地址、HTTPS/本机可达性、密钥权限和负责人状态。客户端如何安装Skill、配置自定义请求头或stdio桥接，以其实际能力为准，不承诺所有AI客户端兼容。

## 升级与必要验证

本批应用0.23、SQL13，renderer/snapshot仍为20。升级前备份客户数据库、媒体、密钥和配置；不以旧数据库覆盖后续业务资料。升级后验证旧设计连接未扩权、新内容范围、候选隔离、同一requestId幂等、富文本图片/链接保护、外部继续调整、真实审核、部分字段采用、新建安全撤销、原生继续编辑及未保存输入保护。

外部模型的文案准确性、业务理解和审美需要用真实授权任务持续评估；自动化回归证明的是权限、候选与草稿流程，没有把测试用例结果当作内容质量或SEO效果承诺。
