# 上线检查工作台

入口为“站点设置 → 上线检查”，建站流程的“检查与发布”也显示同一份工作台。它把已知问题、已配置资料和仍需用户验证的部分放在一起，不设置额外发布门槛，不自动发布、取消noindex或修改网站。AI、Google及关键词服务均可选；不用站内AI也能通过模板、手工编辑或外部AI建站。

## 状态含义

| 状态 | 含义 |
| --- | --- |
| 已配置 · 待验证 | 字段或部署开关已保存，尚未证明服务连通或持续可用 |
| 尚未验证 | 没执行、回执过期、配置版本不符或本次范围不能确定；不等于服务故障 |
| 检查通过 | 只在该条说明的时间、对象和检查范围内取得证据 |
| 需要处理 | 已确认有差异、缺少正式上线配置或检查发现需要用户判断的内容 |
| 检查失败 | 已执行的那项操作返回失败，其他项目分别记录 |
| 本次不适用 | 例如未启用可选的站内AI，不要求为了上线而购买服务 |

工作台不计算“上线总分”。首页、robots.txt和站点地图的抽样通过，不等于全站检查通过、搜索平台已经收录、SEO排名提升、邮件进入收件箱或AI设计已经让客户满意。本机或内网网址只显示“本机演示，尚未验证公网”，不妨碍继续预览和原有发布流程。

## 两种主动检查

- “检查本站资料”：重新读取当前草稿、当前公开版本、部署配置、已有服务测试回执和备份状态，只保存私有检查时间；不联网。
- “检查正式网站连接”：只读取**当前公开快照**中的正式网站，不使用草稿中尚未发布的新域名。检查首页、robots.txt、sitemap.xml；不存在公开正式地址时保留未验证，不发请求。

进入页面或“刷新已知状态”仅GET读取，不做DNS、AI生成、邮件投递、发布或备份操作。AI连接和邮件测试都链接到原设置入口，须用户主动操作，不会在上线检查里隐式扣模型额度或发送邮件。

## 对象、证据与有效期

- 当前草稿修订与公开版本ID独立显示。公开内容字段的差异会提示用户核对发布范围，不要求把所有私有草稿一起公开。私有邮件/AI配置不是网站内容。
- 正式域名、HTTPS配置和服务器`BETTER_AUTH_URL`分别核对；后台与公开网站分离域名可能是有意部署，需要实际验证，不能只按字符串匹配宣称连通。
- AI字段完整只算已配置。连接测试须对应当前完整配置身份且在24小时内；成功只证明当次连接协议响应，不证明余额、未来稳定性或设计质量。旧建站记录没有绑定模型配置版本，因此仍明确保留为未验证的质量证据。
- 邮件测试按当前配置来源、版本及完整配置身份匹配最近一次回执，24小时有效；最新失败会覆盖旧成功。`mock_sent`只完成本机模拟，始终不能证明真实邮件可用。SMTP测试成功只说明服务接受，用户仍需确认测试邮箱及垃圾箱。关闭询盘自动通知与手工测试配置是独立的，完整SMTP仍可用于账号恢复。
- 本机SEO诊断针对当前草稿，明确已检查目标数和截断范围。公开快照可解析且未设置noindex的地址数只表示收录意图，不是已收录数量。不会为了通过检查自动解除noindex。
- 自动备份开关只证明启动方式有调度配置；最近执行结果来自部署目录下有限的`STATUS.json`字段。缺失、陈旧、失败或未来时间分别显示，不以JSON内容导出冒充完整备份。
- 现有备份工具没有持久化的完整校验及恢复演练回执，该项会明确显示未验证。已有CLI备份、校验、隔离恢复工具继续按部署说明使用，不在此工作台重造恢复操作。

网络抽样回执只保留10分钟，且须同时匹配当前草稿修订、当前公开版本ID和该版本正式地址。后续修改网站或切换公开版本会让旧抽样退回待验证；只读刷新不续期。最新本机检查不冒充新网络检查，仍有效的同对象网络抽样可独立保留。私有回执最多保留50条，过期记录在下一次显式检查时清理。

## API与安全边界

`GET /api/launch-check`返回`LaunchCheckReport`，使用`Cache-Control: no-store`。仅当前仍有效的管理员可读取，服务内也会重新查账号角色和停用状态。

`POST /api/launch-check/check`要求同源、当前管理员，以及精确的并发版本：

```json
{
  "expectedRevision": 12,
  "expectedReleaseId": "release-id-or-null",
  "checks": ["local"]
}
```

无公开版本时`expectedReleaseId`必须是JSON `null`；`checks`只允许`local`、`public-website`或两者各一次。多余字段、任意URL、传输器等被拒绝。检查开始和完成后的保存事务都会重新核对权限、修订及公开指针；不匹配返回409，不把过时结果保存成当前成功。请求取消不保存新回执。

公网传输使用原生HTTPS：只允许服务端公开快照的HTTPS源及三个固定路径；禁止凭据、额外路径和查询；全部DNS解析地址须是公网，内网、回环、链路本地、元数据及受限保留地址被拒绝。连接固定已经验证的IP，保留原始Host和TLS域名校验，始终校验证书；总超时12秒，每个响应最多128KiB，不跟随重定向，不重试，不访问地图中的链接，不向外发送会话Cookie、密钥或客户资料。错误不回显外站正文、IP或底层异常。

robots只分析Googlebot访问首页的有限规则；训练机器人禁令不冒充搜索禁令。404本身不视为禁止抓取，复杂匹配保留未验证。站点地图只抽查最多100个同源地址，首页规范地址与noindex也仅依据本次取得的HTML/响应头。首页公开版本标记不符会提示人工核对域名或缓存，不称当前站点已验证。

## 文件和维护

- DTO：`src/lib/launch-check-types.ts`；服务：`src/server/launch-check.ts`；受控网络层：`src/server/launch-check-http.ts`。
- SQL16追加`cms_launch_check`及私有服务测试回执表；状态、回执、SMTP/AI凭据均不进入公开快照、模板包或MCP授权。
- 服务测试回执由原AI/邮件显式测试入口记录，读取复用`service-test-evidence.ts`和`mail-test-evidence.ts`。完整配置指纹仅服务端HMAC，不返回浏览器。
- 新功能不增加依赖、不改变原发布确认和备份格式。升级后验证角色/同源、并发保护、回执匹配与过期、模拟与真实结果区分、本机零公网请求和私有数据隔离。

定向单元命令：`npx tsx --test tests/launch-check.test.ts`。其中受控依赖返回的网络响应均为合成测试资料，只验证解析、状态和并发边界，不能作为客户真实域名/TLS验收。`tests/launch-check-http.ts`供生产构建集成测试调用，公网按钮只测隔离本机/无网址场景，不建立任何生产网络白名单或环境后门。
