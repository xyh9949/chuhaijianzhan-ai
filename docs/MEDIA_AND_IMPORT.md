# 素材与批量导入

## 图片和目录

图片输入仍限制静态JPEG/PNG/WebP、8 MB、4000万像素，真实解码、方向纠正、重编码WebP并剥离原EXIF。记录重编码后的固有宽高和实际字节数；原文件URL/哈希不变，新图按原宽度生成小于原图的320、768、1440px衍生尺寸，不放大。衍生URL为原地址加`?width=320`等白名单值，可按原资源重建，原图仍可下载。

Image组件可选自动/原尺寸/固定档位；自动模式使用srcset/sizes，缺少该档位时沿用原图。产品卡片、图片字段、图库和轮播也提供固有尺寸及lazy/async属性。四张内置演示图尺寸按实际文件记录。旧上传素材没有新元数据时仍按原URL显示，不强制迁移历史。私有预览使用原图，避免把data URL拼接尺寸查询；后续升级需回归此边界。

PDF目录最多10 MB、1000页，校验MIME、.pdf扩展名、签名和结束结构，再由pdf-lib解析结构。加密或含JavaScript/Launch/嵌入附件/主动表单等内容拒绝；解析在worker中进行，V8堆上限128 MB、8秒超时，原始解析器错误不进入应用日志。这是基本有效性和受限解析，不等同杀毒或完整PDF合规认证。

PDF以附件、nosniff和sandbox CSP返回，不在网站内嵌执行。可拖入“PDF目录下载”组件选择目录；预览不触发附件下载，公开发布后可下载。目录和图片/视频按类型检查，不能把已知PDF素材充当图片。视频仍40 MB、MP4/WebM基础签名检查，不转码。

后台素材可搜索、按文件夹筛选、勾选/批量移动或移出草稿库。每批1–500份，任何草稿引用都会拒绝整批移出，不部分删除。引用详情覆盖页面、同步区块/卡片、产品、独立内容、全站样式/代码及历史版本。历史版本仍保留文件，移出草稿库不会物理删除。

容量只统计本实例上传持久目录（不含随应用交付的四张演示图），按实际物理文件去重区分原资源和衍生文件，另显示磁盘可用空间、草稿数量和缺Alt数量。这里的空间不是账户配额或无限容量承诺。管理员可看未被草稿素材库和任何历史版本保留的文件清单，当前只读、最多展示2000个文件，不提供物理删除。

## 导入流程和格式

产品管理及内容模型的内容记录页可批量导入。选择CSV/JSON文件，选已有模型，逐列映射字段，预检所有行并查看错误/转换后值，确认后原子新增草稿。支持管理员/编辑员；只读不能导入。不能通过此入口创建模型、替换网站设置、修改账号或覆盖已有记录。

每批最多500行、2 MB原始UTF-8文件；整体草稿仍受4 MB、2000产品/2000独立记录等现有边界限制，不通过分批导入绕过总量限制。超限整批拒绝。默认只新增，不自动发布、不从任意URL下载图片。封面/图片字段使用已上传的本实例图片地址或四张演示图。

CSV：逗号分隔、首行列名、双引号转义，支持引号内换行和UTF-8 BOM。列名最多110列、不得重复；每行列数一致。数字/布尔使用JSON字面值（例如`0`、`false`），多选和图库用JSON文本数组，日期用YYYY-MM-DD。空单元格代表未填自定义值，保留0与false。错误列名/引号/编码不尝试猜测。

JSON明确协议：

```json
{
  "schemaVersion": 1,
  "kind": "product",
  "rows": [
    { "key": "demo-001", "name": "Demonstration product", "sku": "DEMO-001", "quantity": 0, "available": false }
  ]
}
```

独立内容把kind改为entry，行使用key/title并在界面选择已有独立内容模型。自定义列如quantity/available在界面映射到模型字段，不直接携带任意对象或HTML程序。JSON值仅允许文本、数字、布尔、null和文本数组。未映射列明确提示忽略。

产品必映射name/sku；key可不填，以SKU作为幂等导入标识。独立内容必映射key/title；key为1–64位ASCII字母数字/下划线/短横线。同目标/模型的key生成稳定内部ID，重复导入拒绝，不静默更新。SKU不区分大小写判重，短路径在同范围也不能重复。标题可重复，不能拿标题代替稳定key。自定义字段发布必填仍在实际发布检查。

预检不写数据，确认签名绑定文件、映射和草稿revision，5分钟内有效；任何变动需重新预检。写入复用现有SQLite事务与完整草稿校验，失败不留半批记录。已发布站点保持原版本，需另行明确选择新记录发布。

## 部署与升级

新增pdf-lib固定1.17.1，MIT，依据[官方加载API](https://pdf-lib.js.org/docs/api/classes/pdfdocument#load)。worker的require.resolve使用官方turbopackIgnore注释，避免被编译成无法在worker加载的内部数字ID；解析库通过Next官方serverExternalPackages和outputFileTracingIncludes保留原生require及pdf-lib/@pdf-lib/pako/tslib运行文件；不修改依赖源码。部署保留Node worker_threads能力和依赖，短时serverless不是当前交付形态。升级Next或pdf-lib后验证生产上传解析、超时/无效/主动内容拒绝、附件头和打包文件；升级Sharp后验证转向/固有尺寸/衍生重建和原图历史访问。

协议11读取1–10。新增素材元数据均可选，旧数据不强制写新字段；新增Download需新渲染器。回退应用应使用对应版本的一致性实例备份。派生文件可重建，原文件和不可变发布清单不能当作缓存删除。后续扩容方向是分页内容API/索引及对象存储等独立设计，不能只提高全量JSON上限。
