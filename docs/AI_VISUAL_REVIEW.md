# AI 视觉检查

适用版本：0.33.0（兼容0.32首屏与历史截图）。它为已有设计候选增加“看真实截图再提建议”的环节，继续复用原来的预览、生成、确认应用与撤销流程。截图和评审均由管理员本人发起；普通访客和其他管理员不能读取本人的结果。

## 使用流程

1. 在 **站点设置 → AI服务** 保存并启用自己的连接。服务须兼容现有 Chat Completions 接口，并支持 `image_url` 图片输入及 JSON 回答；文本连通测试通过，不代表模型支持图片。
2. 默认文字模型可继续负责写作和生成设计。可单独填写“视觉模型”名称，但它复用同一服务地址和密钥；留空时使用默认模型。当前不支持第二套独立的视觉连接。
3. 在 AI 页面设计、整站设计或详情模板设计中，先生成并打开真实候选预览。整站设计先选要检查的页面。
4. 展开 **让AI看看实际页面（可选）**，选择电脑、平板、手机，点击 **生成真实截图**。默认保留简单首屏；需要长页时展开 **检查更多页面内容**，选择 **滚动检查整页（分段）**、起始段和每台设备本次数量，可同时开启原生交互观察。这一步只在本实例运行浏览器，不调用模型。
5. 核对截图并勾选实际要发送的图片，每次最多3张；可填写检查重点。勾选明确的发送同意后，点击 **发送所选截图检查**，才会把所选图片、要求、真实页段／交互状态信息及相应可见原生节点标识发送给用户自配的模型。整组有更多图片时，只检查本次明确发送的部分，不自动拆成多次收费请求。模型调用可能产生供应商费用。
6. 阅读建议，点击 **在预览定位** 可跳到对应设备的候选内容，短暂描边。只定位存在于该截图原生节点白名单的内容；这不改变网站数据。模型无法可靠定位时，建议仍可人工核对。
7. 点击 **带入继续调整** 只填写原来的追问框。用户核对并点击原来的继续生成按钮后，才调用设计模型创建下一版候选。
8. 对比真实修改前后预览，满意后 **确认应用** 到网站草稿。可按原来的入口撤销；发布仍是独立步骤。最终设计保留原生节点和动态绑定，可继续拖拽修改。

展开、切设备、看历史、定位和带入追问不会自动调用模型。截图或候选过期、候选内容变化后应重新生成截图；旧建议不能绕过现有的采用范围、版本冲突和撤销校验。

## 截图范围与判断边界

- 来自真实 Chromium / Chrome / Edge 浏览器，格式为 JPEG；不用 DOM 拼图或文本示意图冒充截图。
- 电脑初始视口为 1280 × 900，平板为 768 × 1024，手机为 390 × 844。实际截图只包含预览内层页面的可见区域，会扣除预览提示条等空间；界面显示的是实际图片尺寸。
- 默认仅首屏。整页模式以85%视口步长生成重叠页段，记录实际文档起止坐标与最终高度；每设备本次最多6段，可从第1至200段开始。达到本次段数／图片预算时明确标为部分，并可点击继续检查后续页段。只从中间开始的组不会冒称包含前半页。
- 分段覆盖与AI审阅分别计算：即使本组覆盖了外层滚动高度，AI也只看本次勾选的最多3张。页面高度上限100000像素；独立纵向滚动区未逐一遍历、探测元素超过2000等情况明确保留未检查状态。没有拼接长图后缩小到文字不可读，也没有把预算内的前几张冒充整页。
- 使用冻结的本人候选，不接受任意外部 URL，不回退实时草稿。客户自定义 JavaScript 不在截图中运行。
- 截图只允许本站当前候选、本站静态文件和受控媒体的读取。外部图片、字体或其他请求被拦截时可能缺少资源，界面会提示；不能把缺图直接当作设计结论。
- AI 建议可能遗漏问题或判断错误。它不保证整站视觉质量、品牌独特性、无障碍合规、业务事实、SEO 排名或转化效果。基础排版检查和人工完整预览仍保留。

## 部署浏览器

项目运行依赖包含 `playwright-core@1.65.0`。浏览器二进制是可选运行条件，不会因为打开后台而自动下载；缺少它时只关闭自动截图，已有预览和编辑功能保持可用。

部署人员在实际运行服务的同一系统账号下，进入项目目录，执行：

```sh
node node_modules/playwright-core/cli.js install chromium
```

Linux 若缺少浏览器系统库，可由有相应权限的部署人员安装系统依赖：

```sh
node node_modules/playwright-core/cli.js install --with-deps chromium
```

也可使用机器上已安装的稳定 Chrome 或 Edge。系统检测只接受官方标准安装位置，不接受任意可执行文件路径。Windows 检查 Program Files / Local AppData 下对应目录；Linux 检查 `/opt/google/chrome/chrome` 或 `/opt/microsoft/msedge/msedge`。

环境变量由运行该 Node 服务的进程读取；修改后重启服务：

| 变量 | 默认 / 支持值 | 用途 |
| --- | --- | --- |
| `FORM_STUDIO_VISUAL_BROWSER_CHANNEL` | 未设置时依次检测 `chromium`、`chrome`、`msedge` | 显式设置后只使用所选浏览器，不自动切换 |
| `FORM_STUDIO_VISUAL_DISABLED` | `1` 表示关闭，其他值不主动关闭 | 禁用自动截图的运维开关 |
| `FORM_STUDIO_VISUAL_ORIGIN` | 默认 `BETTER_AUTH_URL` 的来源 | 反向代理或容器部署可指向同一实例的本机 HTTP 服务，如 `http://127.0.0.1:3200`；只接受本站来源或 loopback 地址，不接受路径、查询、凭据或任意内网主机 |
| `PLAYWRIGHT_BROWSERS_PATH` | Playwright 默认缓存路径 | 可选的持久化浏览器缓存位置，安装和运行服务时必须一致，并允许服务账号读取 / 执行 |

`BETTER_AUTH_URL` 仍填写正式后台站点来源。不要为了内部截图去修改正式登录地址。内部来源必须能访问同一服务、同一运行数据和有效候选；截图任务不会把浏览器登录 Cookie、后台密钥或会话令牌发给模型。

容器中浏览器及其系统库需要在镜像内安装，缓存可挂持久卷；无浏览器或启动权限不足时，面板会显示无法自动截图的原因。不要用静态占位图让检查显示成功。Playwright 版本升级后应重新安装对应 Chromium，并跑本页末尾的验收。

## 私有暂存与删除

截图字节及评审保存在本实例运行数据库，未放入公开素材中心；图片响应带 `private, no-store` 和 `noindex`，读取时重新检查登录身份、本人归属、候选和有效期。

每组有效期最多 40 分钟，并受原候选更早的过期时间限制。到期后不可读取；后续创建截图 / 评审时清理过期记录，不承诺后台定时即时物理清除。同一候选的已生成截图组可切换重开。界面的 **移除此组截图** 会明确确认，同时移除这组评审历史，不影响原候选、媒体、网站草稿或发布版本。运行数据库备份仍应按实例自己的备份保留规则管理。

当前一台实例同一时间处理一组截图。每张JPEG最多1 MiB，一组最多12 MiB（编码前图片预算8 MiB，给base64与节点信息留空间）；每设备最多6页段加4张原生状态，三端最多30张。本人最多10组、总暂存48 MiB且预留下一组空间。达到图片预算时保留已完成的真实页段和准确的部分覆盖说明。本人视觉评审记录最多 100 条；达到限制可先移除旧组或等待到期。任务失败不伪造结果，已准备的页面候选保持。每次用户主动新建截图时，仅清理本人已过期，或来源明确404／410的失效组及关联建议；403、格式错误或服务异常不会被当成候选删除，GET读取不做清理。

## 验收与维护入口

- 组件：`src/components/AiVisualReview.tsx`、`src/components/AiDesignPreview.tsx`。
- 浏览器运行：`src/server/ai-visual-browser.ts`；私有暂存 / 模型评审：`src/server/ai-visual.ts`。
- 原生定位规则：`src/lib/ai-preview-inspection.ts`、`src/components/SandboxedSitePreview.tsx`。消息同时检查真实 iframe、来源及候选路径；以真实排版回报确认预览就绪，不靠固定延迟发送定位。交互截图中的内容需要在真实预览打开相同状态后核对，定位不会运行任意用户脚本。
- UI 回归：`tests/ui/visual-review.spec.ts` 使用本机合成模型，验证三端真实 JPEG、选图与明确同意、手机切换后的慢装载定位、只填追问、原生继续生成、预览确认、采用及撤销。合成模型验证软件流程，不代表实际视觉审美已验收。
- 执行 UI 用例应使用 `scripts/test-ui.cjs` 隔离包装器，正式实例和正式数据库不参与测试。按 `docs/UI_REGRESSION.md` 配置已安装的测试浏览器后，运行 `node scripts/test-ui.cjs --grep AI视觉检查`。

升级预览渲染、沙箱隔离、节点标识、媒体读取、AI 接口或 Playwright 时，重新核对截图私有权限、资源白名单、无客户脚本、设备尺寸、真实就绪定位，以及确认前不改草稿、撤销后内容恢复和发布指针不变。


## 原生交互的安全检查

“同时检查菜单、标签页等原生交互”只操作平台已知控件，不接受用户传入的选择器、脚本或动作清单：

| 项目 | 实际检查 | 明确边界 |
| --- | --- | --- |
| 菜单／折叠内容 | 点击可见summary，核对details确实open且内容有实际尺寸，再恢复原状态 | 每类最多6个当前可见控件；隐藏或超额项显示未检查，不访问菜单页面 |
| 标签页 | 点击原生radio对应label，核对选中与内容显示一致，再恢复原标签 | 最多3组，每组前4个中的非默认标签；其他项未检查 |
| 轮播 | 点击真实下一项锚点，观察横向位置变化，随后恢复原位置 | 最多3个轮播，只检查到下一项；不是所有幻灯片验收 |
| 同页按钮 | 仅点击平台原生按钮中已存在的#目标，确认目标进入可见范围并恢复位置 | 最多6个；普通页面链接、外链、邮件和下载不会点击 |
| 链接／表单标注 | 读取前120个链接中的同页目标，及前10个原生表单的标签关联／required声明 | 不读取输入值，不填写、不触发校验或提交，不证明询盘送达 |

每个设备最多保存4张交互状态图片，分别用于菜单、折叠、标签、轮播首次实际成功状态；更多本地观察以文字列出。状态截图与页段有不同图片ID。同设备多张图片的模型建议必须指出真实imageId，节点也必须存在于同一张被发送图片中，不能借另一页段的节点提供误导定位。

绿色／“已观察”仅描述具体原生状态已被浏览器看到。未检查、隐藏、预算限制和异常分别列出；它不是全站可访问性、事实、链接可达性或表单端到端验收。所有写请求、外域和非固定候选路径仍被网络白名单阻止，客户JavaScript仍关闭。
