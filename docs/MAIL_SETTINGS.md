# 邮件通知设置

应用0.26.0。管理员进入 **站点设置 → 邮件通知**，可以直接配置询盘邮件服务，不再需要修改服务器文件或重启项目。网站资料里的“公开联系邮箱”仍只用于对外展示，与发信账号、询盘收件邮箱分别维护。

后台入口路径为`/admin?settings=mail#settings`；询盘通知面板上的“配置邮件通知”也会进入同一设置页。

## 配置方法

1. 向你使用的邮箱或邮件服务商取得SMTP地址、端口、加密方式、登录账号及邮件密码或授权码。填写服务商提供的值；部分邮箱使用授权码而非网页登录密码。
2. 填写发件邮箱和接收询盘的邮箱，最多5个收件地址。网站访客不能决定这些收件人，也不能把表单字段当作SMTP配置。
3. 选择加密连接方式。常见为465直接TLS或587 STARTTLS；自定义端口及本机/内网服务放在高级选项，仍使用加密和证书校验。不要在地址中填写`https://`、路径或端口。
4. 保存配置。配置立即供当前实例使用，不需要发布网站。保存不主动发送测试信；开启自动通知后，新询盘及原来等待重试的任务会按通知队列处理。过去“未配置”的旧任务不会因首次后台启用而静默补发，需要在询盘详情核对后单独重试。
5. 填写测试收件邮箱，点击 **发送测试邮件**。只使用已经保存的配置，发送一封不含客户询盘和网站私有资料的固定测试信。尚未保存修改时应先保存或明确放弃修改，不能把未保存值当作已配置服务测试。

自动通知关闭时，也可以测试完整的已保存SMTP配置。测试会明确显示是模拟结果还是邮件服务已接受；服务接受不保证已经进入收件箱，需到目标邮箱及垃圾邮件文件夹核对。

测试按钮有进行中状态和服务端限频：同管理员每分钟最多一次，不自动重试测试。服务器的模拟模式仅供原有本机/部署测试使用，后台不会提供把模拟模式冒充真实发送的选项。

## 密码、旧配置与未保存输入

密码以实例固定密钥派生的AES-256-GCM加密保存于私有数据库。后台只返回“已保存密码”，不会回显明文或密文。相同SMTP服务与账号下，密码留空表示保留；更换服务器、端口、加密方式或账号时，需要填写对应的新密码，或明确移除旧密码，防止把原密码发往新服务。

密码只在当前表单内存中临时填写，不写入浏览器恢复记录、本地存储、站点快照或源码包。离开有未保存修改的表单时，会提示继续编辑或放弃。其他窗口已修改配置时，保存会提示冲突，读取最新配置后核对，不覆盖别人的新设置。

升级后尚未通过后台保存时，继续使用原服务器环境配置，界面会说明来源。第一次保存后，后台配置优先于环境；关闭开关也会覆盖环境中的启用状态，不能因为旧环境仍存在而意外继续发信。没有修改原`.env.local`或把环境密码公开给浏览器。

## 询盘与通知状态

网站询盘始终先可靠入库，邮件失败或关闭不会丢失询盘。询盘详情和原“询盘与通知”设置中可查看待通知、处理中、服务已接受、模拟完成、未配置及失败状态。管理员可以核对后重试允许的任务；已经完成的任务不作为失败重发。

关闭自动通知会停止领取后续任务；已经开始的网络投递不能保证撤回。通知重试沿用至少一次投递语义，服务接受后进程异常仍可能重复通知，不承诺精确一次。错误只显示安全的中文提示和固定错误类别，不把邮件服务商原始消息、口令或客户内容写入后台日志和审计。

## 接口与运维

| 接口 | 用途 |
| --- | --- |
| `GET /api/notifications/settings` | 管理员读取安全配置摘要、版本、来源及是否已有密码 |
| `PATCH /api/notifications/settings` | 同源管理员按`expectedRevision`保存私有配置 |
| `POST /api/notifications/settings/test` | 同源管理员用已保存版本，给明确的`recipient`发送单封固定测试信 |

邮件设置属于单实例运行数据，不参与内容发布、公开快照、网站分发、MCP设计上下文或文章写作。保存设置不改网站内容修订号和公开发布指针。备份与恢复需要保留数据库及原固定密钥；只复制数据库而替换固定密钥会导致密码无法解密，需要重新填写。

回退应用前，在隔离副本核对旧版环境变量和数据库设置。若旧程序无法读取后台当前的 SMTP 设置，应先停用旧环境中的邮件发送，避免通知被发送至先前的服务。[升级和回退](../DEPLOYMENT.md#升级和回退)

本机合成测试和模拟邮件只验证软件流程、权限和队列，不证明真实SMTP服务的账号、网络、认证及收件箱送达。本机另有真实TLS/SNI/认证/单收件人握手，以及拒绝明文降级的SMTP协议测试，使用独立合成证书与测试服务，方法见[本机SMTP测试夹具](../tests/fixtures/mail/README.md)。用户配置真实邮箱后，应主动发送一封测试信并到收件箱核对；测试没有自动接入或购买邮件服务。
