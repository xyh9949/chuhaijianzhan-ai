# 独立内容详情与循环卡片 · 0.6

## 为案例、团队等内容建立详情页

1. 在「内容模型」建立独立内容模型并填写至少一条记录。
2. 从该模型的「创建详情模板」进入页面创建，选择关联模型，填写模板路径，例如 `/cases/:slug`、`/team/:slug` 或 `/projects/cases/:slug`。
3. 系统生成可编辑的初始结构。进入拖拽编辑器，增删容器、文字、图片、按钮，并将需要变化的属性绑定到「当前记录」。页面属性中的「详情模板预览样本」仅用于模板编辑预览。
4. 在内容记录中填写网址标识，例如 `coastal-residence`，并按需填写 SEO 标题和描述。没有填写标识时使用稳定记录 ID；修改内容标题不会改变网址。
5. 发布模型、详情模板和需要上线的记录。模板 `/cases/:slug` 本身不供访客访问；已发布记录会自动生成 `/cases/coastal-residence` 等详情页，不需要逐条复制页面。

每个独立内容模型最多关联一套详情模板，模板关联保存在页面的 `contentModelId`。没有详情模板的模型仍可用于普通页面或内容列表。产品继续使用已有 `/products/:slug` 模板。

同一模型的有效网址标识不能重复，也不能占用另一条记录的默认 ID。系统保留路径、普通页面与生成地址的冲突会在保存和发布时检查。更改已发布记录标识或模板前缀，需要发布后生效；本阶段不自动创建旧地址重定向。

## 设计可重复的卡片

1. 在列表所在页面拖入「自由卡片循环列表」，通过「循环数据来源」选择产品或独立内容；独立内容必须选择模型，产品也可选择「全部产品 / 基础字段」。
2. 在属性面板顶部点击「新建卡片设计」，或通过「卡片设计模板」选择已有同步区块，再点击「编辑卡片设计」，进入同一套拖拽画布。已有卡片时可点击「新建独立卡片」建立另一份设计。
3. 卡片内可以自由添加、移动、嵌套容器、图片、文字、按钮和同步区块。把变化的属性绑定到当前记录，把固定的标签或装饰保留为静态内容。
4. 按钮链接可绑定内置的详情链接。独立内容使用所属模型的详情模板生成地址，产品使用产品详情模板。
5. 点击左上角「返回来源页面」，系统先保存卡片，再返回并选中原循环列表。列表会针对每条记录重复渲染相同设计，各张卡片读取自己的字段和链接。
6. 调整列表列数、间距、显示数量及三端样式，预览手机效果，再选择发布页面、内容记录、卡片区块和详情模板。

循环卡片复用现有同步区块机制，卡片内部的设计可在单独画布自由拖拽；列表里的重复实例用于预览，不能把某一实例改成独立设计。若不同记录确实需要不同卡片结构，应分别创建卡片模板和列表。

原有「内容模型列表」继续保留，适合直接映射标题、说明、图片和链接；新增循环列表适合自由组合卡片结构。

## 数据、样式与发布规则

- 普通页面的当前记录来自页面默认记录；独立内容详情页来自实际访问的记录；循环卡片来自当前循环项。内部同步区块继续继承这一上下文，不能被外层产品 URL 或卡片编辑样本覆盖。
- 同一卡片的不同实例会生成独立样式标识，复制、移动或重复使用时不会互相覆盖响应式 CSS。
- 列表按当前快照中的记录顺序展示，显示数量为 1–50。空列表显示可编辑提示。当前不包含分页、访客筛选器、查询表达式或关系字段。
- 卡片可嵌套容器和同步区块，但不能直接或间接再嵌套循环列表。循环引用、过深引用和展开超过 10,000 个节点会被阻止，避免大列表拖垮页面。
- 修改卡片会影响所有引用它的列表；发布时必须显式选择卡片区块。新增嵌套区块也要一并选择，预检不会自动把其他草稿带上线。
- 记录、模板、列表页和卡片分别选择发布。只发布记录可以更新对应详情及所有引用列表；只发布卡片可以更新多个页面的列表设计。未选择的资料和设计继续沿用公开版本。
- 历史版本保留当时的模板、网址和卡片。切换公开版本不覆盖草稿；选择恢复草稿后还需要另行发布。

## 权限与维护

编辑成员可以维护模板、内容记录、循环列表和卡片草稿。内容模型结构仍仅管理员维护，公开发布和版本切换仍仅管理员执行，只读成员不能保存。

0.6 新发布使用 schemaVersion=4、rendererVersion=4，兼容读取 1/2/3。新增 PageItem.contentModelId、ContentEntry.slug/seoTitle/seoDescription 和 ContentLoop 组件；循环卡片仍保存为 SharedBlock，不另建重复资产库。

共享路由入口为 `lib/content-routes.ts`，渲染仍使用 `site-render-config.tsx`；引用分析与重复展开成本由 `shared-blocks.ts` 处理。没有新依赖、依赖源码补丁或破坏性数据库迁移。

升级前备份源码、数据库、媒体和环境配置。升级依赖后至少复测：内容模板创建、网址冲突、SEO、草稿/公开导航、卡片编辑后返回、当前项隔离、三端样式、部分发布及旧版本恢复。回退应用时恢复匹配的旧数据库和媒体，不用旧程序写入新版数据。
