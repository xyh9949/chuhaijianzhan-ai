# 挑选新增、删除和重排的区块

适用0.30.0。入口：**全站设计 → AI设计整个网站 → 逐页看效果与继续调整 → 只采用部分修改 → 挑选页面内区块**。AI仍由用户自行配置，选择已有方案不会调用模型。

## 普通用户怎样用

生成或打开方案后，除了文字、样式区块，还会看到“新增区块”“删除区块”“移动区块”“替换区块”或“关联区块”。名称取实际区块的图层名称、标题或内容，说明会解释哪些内容需要一起采用。

- 例如AI在首页前部新增工厂介绍，在另一位置删除旧联系区。若它们相互独立，可以只采用新介绍，旧联系区保留。
- 同一位置移除旧区块并换成新区块时，两项合为一个替换组，避免选出缺失或重复的结构。
- 把产品区移到另一个位置时，原位置与新位置是一组，不能只留下半次移动。
- 把联系方式从首屏搬到询价区时，两个完整根区块为一组；独立新闻或文案变化仍可单独选择。

勾选后点击“预览选中修改”，查看新组合的真实页面，再确认应用到网站草稿。原方案保留，公开网站仍需原发布流程。采用后可以继续使用原生拖拽编辑器；七天内无冲突时可撤销。

## 系统怎样保护原有设计

系统比较冻结的前后原生布局，不裁剪模型操作日志。没有改变相对顺序的根区块形成位置骨架，骨架之间的增删替换按依赖成组；跨位置移动、跨根迁移的两端会进一步合并。一个根最多属于一个组。整个组包含完整嵌套内容与实际需要的动态卡片、同步区块、菜单及素材。

组合使用当前工作区为基线。同页未选区块后来的文字和样式编辑保留；选中区块已有手改、共同设置或顶层结构被人工改变时拒绝覆盖。现有和后来新增的锁都会重新检查，锁定内容、位置和祖先样式不能通过“只选一部分”间接改变。某些完整方案的新增与删除会相互抵消位置变化，单独采用其中一项仍可能触及锁；此时需一起选择，或从当前草稿重新调整。

每侧最多100个根、300个节点、16层，候选最多200个区块组，每次最多提交103个单位；过大的源布局回退整页，混合组合超过预算则拒绝，不静默截断。页面共同样式或显隐变化、旧版独立zones布局等仍需整页采用。当前工作区后来发生顶层增删或重排时，也需要重新设计或预览。

这仍是完整顶层区块及依赖组，不支持任意拆开一个容器里的某个后代、属性或祖先样式。继续AI调整仍按页面任务范围，未选状态不是永久锁。采用与撤销继续保护整个受影响页面，避免覆盖预览后的手工修改。

## 外部AI与维护

MCP/Skill沿用原工具、read/propose、页面范围、私有约定权限和人工确认。`selectionUnits`保持整页与全站范围；`sectionUnits`的`nodeIds`为前后根并集，包含已删除根，不能只到after里查找。稳定单根保留原ID；结构或多根组使用新的`section:g1:<hash>`。外部只回传服务器的单位ID，不拆组、不编造位置；失效ID应重读状态，不能自动扩成更大的采用范围。历史选择ID和成功请求回执保持，不能因来源删除或新版重新计算组就重复执行。

组合方案继续保存原生整页 Changes。切换版本时，在隔离副本复核已有候选、结构组的选择范围和撤销。[升级和回退](../DEPLOYMENT.md#升级和回退)

修改分组、候选执行差异、依赖闭包、锁定或撤销保护时，在隔离实例重新验证。
